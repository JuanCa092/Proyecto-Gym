Use Case - Verificar disponibilidad de cupos link

Properties
Name Value
Description

El caso de uso evalúa dinámicamente si una clase elegida por el usuario cuenta con al menos un cupo disponible en el sistema antes de proceder con el registro de la inscripción      .

Use Case Note
■ Workflow
    • El usuario selecciona una clase para inscribirse.
    • El sistema consulta en la base de datos el límite máximo de cupos y la cantidad de inscripciones registradas a esa clase.
    • El sistema calcula los cupos disponibles de forma dinámica.
    • Si existen cupos disponibles, permite continuar con el flujo de inscripción.
■ Business Logic
    • Cupos disponibles = (Cupos máximos de la clase) - (Inscripciones activas realizadas).
    • Si el resultado de cupos disponibles es menor o igual a cero (0), la clase debe marcarse visualmente como "Agotada" o "Sin cupo".
    • La verificación debe realizarse justo antes de procesar el guardado de la reserva para evitar inconsistencias por inscripciones concurrentes.
■ Decisions
    • No se manejan listas de espera cuando una clase alcanza su cupo máximo (fuera del alcance del proyecto).
    • La verificación se ejecuta de forma automática tanto al cargar la vista de clases como al hacer clic en "Inscribirse".
■ Follow-up
    • Evaluar si a futuro se habilitará un indicador numérico en tiempo real que notifique cuando queden pocos cupos (ej. "Últimos 2 cupos").

Scenario
Steps
1. El sistema recibe la solicitud de verificación al momento de consultar clases o al presionar "Inscribirse".
2. El sistema lee el límite de aforo de la clase y cuenta las reservas vigentes asociadas en la base de datos.
3. El sistema determina que el número de cupos ocupados es menor al límite máximo programado.
4. El sistema retorna la confirmación de disponibilidad para habilitar el botón de reserva o dar paso al flujo de inscripción.
