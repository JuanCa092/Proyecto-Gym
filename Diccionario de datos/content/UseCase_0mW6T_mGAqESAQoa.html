Description

El caso de uso permite a un usuario registrado autenticarse en la plataforma GymLocator ingresando su correo electrónico y contraseña      . El sistema valida las credenciales recibidas y, si son correctas, otorga acceso a la plataforma dirigiendo al usuario al panel correspondiente según su rol (Cliente, Administrador o Entrenador)      .

Use Case Note
■ Workflow
    • El usuario ingresa sus credenciales(Correo electronico y contraseña) en el formulario de acceso.
■ Business Logic
    • El sistema debe validar el correo y la contraseña contra la base de datos y otorgar permisos segun el rol (Cliente,Entrenador,Administrador).
■ Decisions
    • Tanto clientes como entrenadores y administradores utilizarán el mismo formulario de inicio de sesión centralizado, siendo la base de datos la que determine su rol y redirección.
■ Follow-up
    • Definir con el equipo si se implementará bloqueo temporal de la cuenta tras cierta cantidad de intentos fallidos consecutivos de contraseña.

Scenario
Steps
1. El usuario navega hacia la pantalla de inicio de sesión de la plataforma.
2. El sistema muestra el formulario de inicio de sesión con campos para correo electrónico y contraseña.
3. El usuario ingresa su correo electrónico y contraseña, y presiona el botón "Iniciar Sesión".
4. El sistema valida la consistencia y formato de los datos ingresados.
5. El sistema busca las credenciales en la base de datos y verifica que coincidan con la cuenta registrada.
6. El sistema crea la sesión activa del usuario y determina su rol de acceso.
7. El sistema redirige al usuario a la interfaz principal asociada a su rol (ej. catálogo de clases para el Cliente, panel administrativo para el Administrador).

Preconditions El usuario debe estar previamente registrado en la base de datos de GymLocator. La aplicación web debe encontrarse accesible desde un navegador compatible.
Post-conditions Se genera una sesión de usuario válida y autenticada en la plataforma, concediendo acceso a las funciones autorizadas para su rol.
Author Equipo de desarrollo GymLocator
Assumptions La base de datos responde de manera fluida a las consultas de autenticación (SELECT). Las credenciales ingresadas corresponden a un usuario activo en la red de gimnasios.
