Description

El caso de uso consulta y verifica la existencia de un usuario en la base de datos de GymLocator utilizando su correo electrónico o número de documento de identidad como criterio de búsqueda, previniendo registros duplicados o facilitando la búsqueda administrativa      .

Use Case Note
■ Workflow
    • El sistema recibe una solicitud de consulta con un identificador (correo electrónico o número de documento).
    • El sistema ejecuta una búsqueda en la base de datos sobre la tabla de usuarios.
    • El sistema determina si el registro ya existe o no en la plataforma.
    • Retorna el resultado (Existe / No existe) al proceso que lo invocó (Registro o Panel de Administración).
■ Business Logic
    • Ni el correo electrónico ni el documento de identidad pueden repetirse en dos o más cuentas de usuario dentro del sistema.
    • La búsqueda debe realizarse de forma exacta y sin distinguir mayúsculas o minúsculas en el correo electrónico.
    • Se ejecuta automáticamente durante el proceso de registro antes de realizar el guardado en la base de datos.
■ Decisions
    • La consulta es un proceso interno/subfunción invocado principalmente por el flujo de registro de clientes y la búsqueda por parte del Administrador.
■ Follow-up
    • Garantizar la creación de índices en la base de datos para los campos email y documento para optimizar el tiempo de respuesta.

Scenario
Steps
1. El sistema recibe el parámetro de búsqueda (correo electrónico o número de documento).
2. El sistema realiza la consulta directa a la base de datos en la tabla de usuarios.
3. El sistema confirma que no existen coincidencias previas registradas.
4. El sistema retorna la respuesta "Usuario no existe" habilitando el flujo normal de registro o la acción requerida.
